# kb-retrieval-eval 设计卡（M1）

## 要解决的问题
客服知识库问答答错，常常不是模型的问题，而是没检索到对的段落：切块切坏了、关键词没对上、同义说法没覆盖。这个项目演示怎样单独评测“检索这一步”：一组带标准答案段落的问题，几种切块和检索设置，算出命中率并找出每道失败题的原因，再用数据决定用哪种设置。

全部数据虚构（品牌青柚家电，可复用 support-answer-check 的知识库思路但自写一份），不调用真实模型，不用向量库：用两种确定性检索器（关键词 BM25 和字符二元组重叠）。Python 3.10+，只用标准库。

## 目录
```
kbeval/
  __main__.py  # 命令行
  chunk.py     # 切块：按标题切、按固定字数切（带重叠）；每块记来源文档、标题路径、起止位置
  retrieve.py  # 检索器：bm25（自己实现，中文按字和二元组切词）、bigram_overlap
  metrics.py   # recall@k、MRR、命中但排名靠后的题
  diagnose.py  # 失败题归因：答案被切断 / 关键词不重合 / 被相似段落挤掉
data/kb/*.md            # 6 篇虚构知识库
data/questions.jsonl    # 40 题：问题、能回答它的原文句子（gold），不写块编号
tests/
```

## 关键规则
1. gold 用原文句子表示，不用块编号：换切块方式后，自动判断哪些块“完整包含”这句话。一句话被切断在两块之间 → 记为“答案被切断”。
2. 评测矩阵：切块方式（按标题；固定 200 字重叠 0；固定 200 字重叠 50）× 检索器（bm25；bigram）× k（1、3、5）。每格输出 recall@k 和 MRR。
3. 失败归因只用确定规则：答案被切断；问题和 gold 句的词重合为 0（列出问题里的词和 gold 里的词）；gold 所在块排在第 k 名之外，并列出排在它前面的块。
4. `eval --out PATH`：跑完整矩阵，写 JSON 报告；`compare A B`：两份报告逐题比较，列出变好和变坏的题；`explain QID --config ...`：打印这一题的检索结果和归因。
5. 推荐：报告末尾按“recall@3 最高，其次 MRR，再其次块数少”选出推荐设置，并写明理由；这是对这组虚构数据的结论，不推广。
6. `export --out PATH`：给网站演示页的 JSON，不含绝对路径；重复运行逐字节一致。

## 必须写的验收测试
1. 按标题切块时，每块的标题路径正确；固定字数切块时，重叠恰好为设定值，最后一块不丢字。
2. 一道 gold 句跨两块的题，在固定 200 字无重叠时被判“答案被切断”，在重叠 50 时不再切断。
3. 手算一个 3 文档小例子的 BM25 排名，和程序一致。
4. recall@k 和 MRR 在给定小例子上等于手算值。
5. `compare` 能列出两份报告间变好和变坏的题，题数对得上。
6. 换检索器不改变 gold 判定；同一配置跑两次结果逐字节一致。
7. 导出无隐私信息。

证明测试不是摆设：去掉切块重叠、把 MRR 的倒数排名改成排名、让 BM25 忽略文档长度归一化，各自跑测试，贴出失败，再改回。

## 不做
不接真实模型和向量库，不做网页（网站演示页另做），不做答案生成。

## M2

1. 在 `data/kb/synonyms.json` 维护一份短而明确的同义词表，把用户问法映射为知识库用了的表述。BM25 和字符二元组检索在计分前各自对扩展词分词。只匹配原问题做一轮扩展，原词权重为 1，新增词默认权重为 0.5，可设为 0 到小于 1 的值。同一个词只计一次，原词与扩展词重合时保留原词权重。
2. `eval --expand` 在 M1 的 18 格上增加关闭和开启扩展的对照，共 36 格。关闭时重现 M1。每次评测分别报告原有 40 题和 8 道留出题。`compare` 可用同一份 M2 报告配对比较开关，沿用 M1 的前 k 名判定，列出变好、变坏的题号，并给每道变坏题标出新超过标准答案块的块及其来源范围。只在原有 40 题上选推荐配置。
3. 先写定 8 道新留出题，再查看原有 40 题中的失败并写同义词表。README 说明原题有几道发生变化，并注明看过失败再写词表会使原题收益偏乐观。留出题单独计分，留出结果不用于修改词表。
4. 保留 M1 的测试和默认命令。新增测试用手算检查两种检索器的扩展权重，比对关闭时的 M1 结果，验证变好和变坏题及挤掉答案的块，并确认留出题单独报告。临时让扩展词按满权重计分、临时静默关闭扩展，各运行测试并记录失败，随后恢复并跑完整测试和 README 命令。全程只用 Python 3.10+ 标准库，离线运行。
